# Heddle v0.11.0 — Release Notes

- **Date:** 2026-11-07
- **Previous version:** v0.10.0 (2026-11-06)
- **Breaking changes:** Yes. The runtime now rejects some messages
  that v0.10.0 accepted (see Migration §1). The wire contract in
  `schemas/v1/` is unchanged.
- **Total commits since v0.10.0:** 8 (excluding merge commits, including the release commit)

## Summary

v0.11.0 closes two gaps that the v0.10.0 notes listed under Known
limitations. Both bring the Python runtime in line with the v1 wire
contract that v0.10.0 published.

- **Strict parsing.** The runtime now rejects every frame and body
  the v1 schemas reject. Before, it accepted more than the schemas
  allowed, and it could re-emit a timestamp without an offset that
  then failed the frame schema.
- **Middleware-Lane propagation (DESIGN_INVARIANTS #22).** `_` keys
  now travel on every hop: the router's forward, a worker's result,
  an orchestrator's final result, and the subtasks an orchestrator,
  pipeline or council dispatches for a goal. The router no longer
  rebuilds the frame of a task it forwards.

The conformance fixtures grow from 19 to 24 and pin the new
behavior.

## Migration

### 1. Messages the runtime now rejects

These now fail at parse. Workers and routers log the message and skip
it (Invariant 8):

- An `occurred_at` or `recorded_at` that is not an RFC 3339 string
  with a UTC offset. This covers a timestamp without an offset, a
  naive `datetime` in process, an epoch number, and an explicit
  `null`. An **absent** timestamp is still filled in.
- A `TaskResult.processing_time_ms` or `token_usage` value sent as a
  numeric string or a boolean. An integral float such as `420.0` is
  still accepted, as JSON Schema `integer` allows.

A producer that already sends what the schemas allow needs no change.
The new invalid fixtures `frame_timestamp_without_offset`,
`frame_null_timestamp`, `frame_epoch_timestamp` and
`body_task_result_number_as_string` show the rejected forms.

**Stored events.** `heddle.contrib.events` replay parses stored frames
without skipping. An event stored under v0.10.0 with a timestamp that
lacks an offset would now stop replay of its aggregate. No Heddle
component produces such a timestamp, and no such producer is known.

### 2. Carrying `_` keys in your own actors

If you write an actor that publishes a message because of an inbound
one, copy the inbound frame's `_` keys onto the new frame with the
new helper `heddle.core.envelope.middleware_lane()`:

```python
from heddle.core.envelope import middleware_lane, parse, wrap

envelope, body = parse(data)
...
wrap("core.TaskResult", result, **middleware_lane(envelope))
```

Then call `inject_trace_context` as before. Heddle's own workers,
router, orchestrators, pipeline and council already do this.

## Dependencies

The published minimum versions are unchanged. The development lock
moved to duckdb 2.0.0, fastapi 0.162.1 and pydantic 2.14.3, among
others. `duckdb>=1.4.2` already allowed duckdb 2.0, so installers
could get it before this release too.

duckdb 2.0 reads and writes database files created by 1.x and leaves
them readable by 1.x. A database file **first created** by 2.0 cannot
be opened by duckdb 1.x. This matters for the Workshop store
(`~/.heddle/workshop.duckdb`) and `contrib.duckdb` files only if you
create one on 2.0 and later go back to 1.x.

## Known limitations

Carried over from v0.10.0, minus the two fixed in this release:

- **The language SDKs are not compatible yet.** The .NET, Swift and
  JVM SDKs on `heddle-sdk` `main` still speak the pre-`WireEnvelope`
  flat format
  ([heddle-sdk#4](https://github.com/getheddle/heddle-sdk/issues/4),
  [heddle-sdk#5](https://github.com/getheddle/heddle-sdk/issues/5)).
- **`heddle.contrib.events` is experimental and frozen.** It receives
  no new features and its delivery guarantees are unproven
  ([heddle#55](https://github.com/getheddle/heddle/issues/55)).
- **CI does not exercise a live NATS/JetStream broker.** Green CI does
  not certify broker restart, redelivery, or cross-language behavior.
- **Document processing:** the default OCR engines are not installed by
  the `docproc` extra, and `has_tables` / `sections` metadata is
  always empty
  ([heddle#58](https://github.com/getheddle/heddle/issues/58)).

The CHANGELOG has the complete list of changes.
